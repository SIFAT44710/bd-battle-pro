1. EXECUTIVE SUMMARY & MISSION STATEMENT
================================================================================
BD Battle Pro (commercialized as ARENA X) is Bangladesh's first dedicated, 
mobile-first tournament operating system tailored specifically for Free Fire 
12-Squad competitive matches.

In Bangladesh, over 10,000 independent gaming communities and organizers run 
daily Free Fire custom room tournaments. Currently, 99% of these organizers 
manage their matches manually through WhatsApp groups and Messenger chats. This 
manual workflow is plagued by:
- Hundreds of chaotic inbox messages per match.
- Fraudulent players sending edited fake bKash/Nagad payment screenshots or 
  recycled Transaction IDs (TrxID).
- Slow, manual slot allocation prone to double-booking.
- Leakage of Custom Room IDs and Passwords to non-paying players.
- Manual end-game scoreboard counting, resulting in disputes and delayed prize payouts.

BD Battle Pro eliminates this chaos by providing an end-to-end autonomous, 
zero-commission tournament platform that automates payment verification, slot 
reservation, room credential distribution, and scoreboard generation.

MODULE 4: AUTONOMOUS WHATSAPP AI BOOKING BOT (whatsapp-bot)
--------------------------------------------------------------------------------
1. Engine & Runtime:
   - Built on @whiskeysockets/baileys (WhatsApp Web Multi-Device protocol).
   - Standalone Node.js service running 24/7 on Render.com cloud container.
2. Mobile-First Web Pairing Code Interface (server.js):
   - Solves the mobile-only organizer challenge: Organizers who only have a 
     smartphone do NOT need a PC or second camera to scan QR codes.
   - Built-in web server exposes port 3000 (or $PORT) with a Facebook Dark UI.
   - Organizer opens the URL on their phone, enters their WhatsApp phone number, 
     and clicks "Get Pairing Code".
   - Bot calls sock.requestPairingCode(phone) and displays an 8-character code.
   - Organizer types the code into WhatsApp > Linked Devices > Link with phone number.
3. Conversational Booking Flow (services/whatsapp.js):
   - Step 1 (Match Discovery): When a player sends a message, bot fetches live 
     matches from Firestore. If no match is specified, bot replies with a clean 
     list of all active matches, maps, times, specific entry fees, and free slots.
     It asks the player: "👉 আপনি কোন ম্যাচে অংশগ্রহণ করতে চান? (যেমন: Match 1 বা Match 2)"
   - Step 2 (Fee & Payment): Once match is selected, bot requests Send Money for 
     THAT specific match's entry fee (e.g. ৳100 or ৳150) to the organizer's numbers.
   - Step 3 (Payment Verification): Accepts text TrxID or multimodal screenshot. 
     Validates amount against match entry fee.
   - Step 4 (Squad Details): Collects squad name, leader name, and preferred slot.
   - Step 5 (Atomic Booking): Calls bookSlotInFirestore. If slot is occupied, bot 
     politely lists all remaining free slots. If successful, bot returns full 
     ticket confirmation and website link for room password retrieval.
4. Resilient Multi-Model AI & Offline Fallback:
   - 50/50 round-robin rotation between gemini-2.0-flash and gemini-1.5-flash to 
     distribute API call volume and avoid rate limits.
   - Built-in parseBookingWithRegex fallback: If Gemini API quota expires or returns 
     401/429, bot automatically parses Banglish text, extracting slot numbers, squad 
     names, leader names, and TrxIDs with zero downtime.

6. SECURITY, OBFUSCATION & ANTI-FRAUD SPECIFICATIONS
================================================================================
1. TrxID Duplicate Detection:
   - When a slot booking is submitted, firestore.js queries all existing slots 
     across all matches for the submitted TrxID.
   - If a match is found, the transaction is rejected with error DUPLICATE_TRXID, 
     preventing fraudulent multiple bookings with one payment.
2. Phone Verification for Room Access:
   - Room credentials are never broadcast globally.
   - The player client requires matching the exact 11-digit mobile number registered 
     at the time of slot booking.
3. Obfuscation & Build Isolation:
   - Developer maintains readable code in src_backup/.
   - Production build outputs encrypted scripts into root index.html, player.html, 
     and admin.html.
